# Phase 5F: NBA one-credit probe hardening

Status: **offline implementation only**. No provider call, live approval, license change, subscription, secret, migration, workflow, commit or deployment was made.

## What changed

- The one-event `player_points` probe now writes a durable, exclusive-create claim keyed by approval ID under `data/nba/quota-probe/claims/` **before** quota reservation or any HTTP request. The claim is never refunded or deleted. A zero-credit response, HTTP error, network uncertainty or process crash cannot reuse that approval on the same local filesystem. The NBA request gate also refuses a second ledger attempt with that approval ID and refuses to spend a probe-scoped approval in another workflow. A separate-process test proved that two concurrent processes cannot both claim the same approval. A new explicit approval ID is required for any later attempt. The local filesystem is the coordination boundary; do not run the same approval on another machine or a copied workspace.
- The NBA adapter validates `x-requests-used`, `x-requests-remaining` and `x-requests-last` as nonnegative integers. Valid used/remaining readings enter the quota ledger as provider snapshots. Missing or inconsistent headers remain unknown and trigger an `NBA_BREACH` marker; they never become a zero charge. A reported cost over the reserved amount is recorded at its actual value, marked as a breach, and future NBA reservations are denied. The request has a 15-second timeout and no retry. Quota settlement is attempted once; if it is uncertain, the claim remains consumed.
- Dashboard metadata intake accepts exactly `plan`, `limit`, `used`, `remaining`, `observedAtUtc`, `resetDateUtc`. It rejects stale, future, inconsistent or extra fields and writes a sanitized pending record locally. Its optional ledger recording requires independently verified account identity and plan configuration with matching limit and reset date. It cannot change account identity, license, quotas or approval.
- A separate NBA `/events` discovery command uses only the documented zero-market route, one explicit request approval, a durable one-use claim and a zero-credit reservation. It never imports or calls the event-odds adapter. No automatic event selection or billable odds retrieval follows discovery.
- The player-prop parser quarantines malformed books, markets and outcomes while retaining valid pairs. Lines explicitly flag unresolved player identity; source and capture timestamps remain in the pregame snapshot contract. Different lines stay separate, incomplete sides are reported, and books with no market are reported.

## Remaining NO-GO conditions

The Odds API license record still grants no uses. The shared account remains `unverified-may-share`, with an unknown plan/limit, a blocking reason and no live approval. Current monthly headroom and a verified same-account provider counter are unknown. The dashboard intake deliberately stores pending evidence until account identity and plan are independently established; the probe quota gate still requires a fresh recorded provider snapshot and preserves the NBA 206/month, 15/day and peer reserve. The events command likewise remains blocked. No local-only claim can coordinate a copied workspace on another machine, so a later approved probe must be explicitly restricted to this workspace and ledger.

The hook command found in `.codex/hooks.json` is the `PostToolUse`/`Stop` Impeccable detector: `[ ! -f ".agents/skills/impeccable/scripts/hook.mjs" ] || node ".agents/skills/impeccable/scripts/hook.mjs"`. A local PowerShell reproduction fails to parse at `[ ! -f ... ]` with `Missing type name after '['`. No invocation log was found to prove that this was the earlier reported event. The hook was not changed or bypassed. It is a UI design detector; it does not gate or alter these NBA server-side files. No active Git hook is configured in this worktree.
